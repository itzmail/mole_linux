### Changelog

1. **mo clean**: Fixed dry-run nested directory double-counting in potential space calculation
2. **mo clean**: Corrected Docker storage accounting when daemon incorrectly reports active images as reclaimable (moby/moby#51775)
3. **mo clean**: Isolated SQLite handle probe timeouts so timeout on a single database doesn't cancel remaining cleanup tasks
4. **mo clean**: Fixed open-handle probe debug leak where `--debug` traces could falsely downgrade database state to busy
5. **mo clean**: Added a 200MB minimum threshold for build artifact hints to reduce noise from tiny build directories
6. **mo status**: Cleaned up the Processes TUI card by dropping the zombie row and reserving all 3 rows for top active processes
7. **mo remove**: Enhanced directory safety checks for relocated config paths to ensure only exclusively Mole-owned directories are removed
8. **mo update**: Prioritized local install receipts over default global paths when resolving update channels

### 更新日志

1. **mo clean**：修复 `--dry-run` 预览模式下嵌套子目录在潜在可释放空间计算中的重复统计问题
2. **mo clean**：修复 Docker 引擎错误将正在使用的镜像报告为 100% 可释放时的统计偏差 (moby/moby#51775)
3. **mo clean**：隔离 SQLite 句柄检查超时，单个数据库探测超时不再中断后续清理步骤
4. **mo clean**：修复 `--debug` 模式下调试日志泄露至句柄探测缓冲区导致误判为忙碌的问题
5. **mo clean**：为构建产物提示增加 200MB 最小展示阈值，避免微小目录产生冗余提示
6. **mo status**：优化进程卡片 TUI，移除僵尸进程行并完整保留前 3 个活跃进程展示
7. **mo remove**：增强自定义配置路径的安全检查，仅移除完全归属 Mole 的配置目录
8. **mo update**：更新通道解析优先采用当前安装实例自身的 receipt，避免受默认路径干扰
